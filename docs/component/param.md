# param — 参数存储组件（FlashDB 托管，AoModbus 执行上下文）

被动组件（**非活动对象**）：启动加载配置、配置写入的变化检查与**同步固化**。固化发生在
`AoModbus` 保持寄存器写回调内（协议决策：固化失败 = 整笔拒绝 EX04），因此参数模块与
Modbus 共享执行上下文，无独立队列、定时器与状态机。总体设计见
`docs/qp-application-design.md`。

> 不建独立 AO 的依据（活动对象划分规则）：参数模块无自主行为、无独立响应期限；"写入
> 动作 = 生效 + 固化一体"的原子语义要求固化在写回调返回前完成，独立 AO 的异步固化
> 无法给出 EX04 语义。QV 协作调度保证 fdb 调用串行，无并发访问。

## 1. 基线与范围

| 项目 | 内容 |
| --- | --- |
| 需求 | 上位机每次配置写入动作经变化检查后**同步**固化到片内 Flash；固化失败整笔拒绝并如实上报；掉电不丢/不坏；磨损受控 |
| 存储 | FlashDB KVDB（FAL 模式），分区 `fdb_kvdb` = `0x0800F000..0x0800FFFF`（4 KB，4×1 KB 扇区）；`FDB_WRITE_GRAN=8` |
| 独占资源 | `fdb_kvdb_t` 实例、FAL、片内 Flash 参数分区（唯一调用者 = `AoModbus`） |
| 状态 | `snapshot[8]`（最近成功固化的配置 + 有效标志）、`dev_addr`（最近固化地址）、`db_ok`、`load_failed[]`（b2 清除依据） |
| API | `fal_init()`、`fdb_kvdb_init()`、`fdb_kv_get_blob()`、`fdb_kv_set_blob()`、`fdb_kv_set_default()`（`flashdb.h`） |

## 2. FlashDB 托管结论（代码依据 `middleware/flashDB/src/fdb_kvdb.c`）

| 能力 | 结论 | 依据 |
| --- | --- | --- |
| 掉电保护 | **可完全托管** | KV 状态分阶段写（`FDB_KV_PRE_WRITE`→`FDB_KV_WRITE`，`FDB_KV_PRE_DELETE`→`FDB_KV_DELETED`，`create_kv_blob`/`del_kv`）；每 KV CRC32（`create_kv_blob` 计算，`read_kv` 校验）；`_fdb_kv_load()` 上电恢复：PRE_WRITE 置 ERR_HDR 丢弃、PRE_DELETE 经 `move_kv` 找回旧值（`check_and_recovery_kv_cb`）、GC 中断续做（`check_and_recovery_gc_cb`）、坏扇区自动格式化。`fdb_kv_set` 中途掉电只可能留下旧值或完整新值 |
| 磨损均衡 | **可托管** | 追加写 + 脏扇区 GC（`do_gc` 移活 KV 后 `format_sector`），`db_oldest_addr` 旋转使擦除轮转全部 4 扇区（next-generation 模式）。4 KB 分区可用约 3 KB（保 1 空扇区，`FDB_GC_EMPTY_SEC_THRESHOLD`），8 通道 × 20 B 配置远小于容量 |
| 无变化写跳过 | **FlashDB 不提供，必须自做** | `set_kv()` 无条件 `new_kv_ex`+`create_kv_blob` 再删旧 KV，不比较新旧值——同值写同样消耗一条记录并最终触发 GC。因此"校验参数有变化"由本模块的 memcmp 守门 |
| 并发 | 单线程安全 | 全部 fdb 调用只发生在 `AoModbus` 的 RTC 步（初始转换 + 写回调，QV 串行）；`fdb_kvdb_control(SET_LOCK/UNLOCK)` 不设 |

推论：**完全托管成立**，应用侧只需保留变化检查 + 结果上报。

## 3. 对外接口（`app/component/param.h`）

| 函数 | 调用点 | 语义 |
| --- | --- | --- |
| `param_boot_load(&result)` | `AoModbus` 初始转换（`QActive_start` 上下文，`QF_run` 前） | `fal_init` + `fdb_kvdb_init(默认表)` + 逐键加载校验；`result` 返回：每通道配置与有效性、`dev_addr`、初始化/加载失败标志（供 b2/b3 锁存） |
| `param_save_cfg(ch, cfg)` | `AoModbus` 保持寄存器写回调 | 变化检查（`memcmp` vs `snapshot`）→ 同步固化 + **写后读回校验**（`fdb_kv_get_blob` 比对，应答以 flash 实际状态为准）；返回 `PARAM_OK`（读回=下发值，已固化并生效）/ `PARAM_NO_CHANGE`（同值，免写）/ `PARAM_ERR_WRITE`（读回≠下发值，按未固化处理） |
| `param_save_addr(addr)` | 同上（寄存器 128） | 同上，作用于 `dev/addr` |
| `param_set_default_all()` | 恢复出厂（扩展点，暂无寄存器入口） | `fdb_kv_set_default()`：格式化分区并重写默认表 |

读回一致即更新 `snapshot`；不一致**不更新**（操作人员重写寄存器即重试，差异检查自然再次
命中）。同值免写（`PARAM_NO_CHANGE`）不计作固化成功：b1/b2 的清除以真实写入并读回一致
为准。**不做任何兜底**：无自动重试、无掉电前补写、无延迟合并写。

## 4. 写路径语义（同步固化，整帧拒绝）

```text
写帧（限单个通道块或设备寄存器，空档天然隔断，见 ao_modbus §4/§6）：
    新参数 vs snapshot：无变化 → EX 00（不写 flash）
    有变化 → param_save_*() 同步固化（写 + 读回 memcmp）：
        读回 == 下发值 → snapshot 更新 → 调用方更新镜像/发布 CONFIG_SET_SIG → EX 00
        读回 != 下发值 → 镜像不动、不发布、b1 置位 → EX 04（SLAVE_DEVICE_FAILURE）
    （应答以读回为准，不依赖 FlashDB 返回码）
```

- **EX 00 = 生效且已固化**（或同值免写）；**EX 04 = 本次写入既未生效也未固化**。
- 写帧限单通道块/设备块的动机：每回调至多一次 KV 固化（≤30 ms），同时给出帧级原子性
  （多通道帧部分固化的掉电分歧不复存在）。
- 掉电窗口（§2）保证 KV 旧值或完整新值。历史分歧角（库报错但新值已完整落盘——
  ① 替换序列收尾删旧 KV 的状态写失败；② 末步 `FDB_KV_WRITE` 状态写实际成功但校验误报）
  已由**写后读回校验**收口：读回一致即回 EX 00，不再出现"EX 04 但已固化"的分歧。
  残余窗口仅为"写失败且读回也误判、但落盘正确"的双重硬件故障——产品报废级故障域，
  不做额外设计。

### 固化方案选型记录（为什么是同步，2026-11 复审）

复审过两种异步方案并与同步对比（工厂数据采集板卡场景：配置写低频有人值守、
长期无人值守运行、掉电常态、配置正确性决定测量正确性）：

| 方案 | 要害 | 结论 |
| --- | --- | --- |
| 异步 V1：先应答，固化成功才生效，失败回退镜像 | 守住"运行=已保存"；但应答后可能回退违反 Modbus"应答即提交"语义（主站不回读则失败揭示退化为仅 b1），且需暂定/已提交双镜像+代次号处理并发写竞态 | 异步中的正确选择，但整体不如同步 |
| 异步 V2：先生效，异步固化失败仅报 b1 | 配置生效未保存，掉电静默回退旧配置——测量设备行为随电源周期漂移的最坏静默失效 | 淘汰 |
| **同步固化（采用）** | EX 00=提交/EX 04=拒绝，调试现场即时重试；无回退/代次/暂定镜像复杂度；单块限制换帧级原子性，最坏应答钉在 30 ms | **采用** |

**改用异步 V1 的触发条件**（出现任一再切换）：① 上位机单请求超时 < 50 ms 硬约束；
② 必须支持一次 FC16 跨多通道块批量写；③ 要求固化长操作绝对不落在任何应答路径上。

## 5. 加载语义（绝不顶替运行）

| 情形 | 行为 | 上报 |
| --- | --- | --- |
| 键加载成功（含出厂首启默认键） | 发布 `CONFIG_SET_SIG`，通道投入运行（先检后测） | 无 |
| 键缺失 / KV 损坏（CRC 跳过）/ 语义非法（校验拒绝） | **不下发**，对应通道不投入运行（状态 1，等上位机下发） | b2（`load_failed` 记账） |
| 部分成功部分失败 | 成功通道照常启动 | 只对失败参数报 b2 |
| `dev/addr` 加载失败 | **默认地址 1**（唯一允许的默认兜底，保证上位机可达） | b2 |
| `fdb_kvdb_init` 失败 | 无任何配置可下发；Modbus 按默认地址运行 | b3（复位前不清） |

b2 清除：对应参数随后**成功固化**一次即清除；b1 清除：任一后续固化成功；b3 不清除。
上位机对失败通道重写配置寄存器 = 启动该通道 + 固化 + 清 b2，一步到位。

## 6. KV 布局与格式

| 键 | 值（blob） | 说明 |
| --- | --- | --- |
| `cfg/ch1` .. `cfg/ch8` | `ch_config_t` 本体（20 B，无版本头） | 每通道独立键：单通道写不牵动他通道 |
| `dev/addr` | `u16` 本体（2 B） | 从站地址；校验 1..247 |

出厂默认参数由 **FlashDB 默认表**承载：`param_defaults.c` 提供唯一的默认数据源
（`fdb_kv_pair_t` 表：`cfg/ch1..8` 与 `dev/addr`，值为参数本体），传给
`fdb_kvdb_init()`。键集是**底板 8 位置布局**：装配数（`CH_CONFIG_CHANNEL_COUNT`）少于 8
的 SKU，未装配通道的键仍由默认表物化但不被加载/使用（加载循环以装配数为界）。空 flash（全扇区头坏）时 `_fdb_kv_load()` 走 `fdb_kv_set_default()`
把全部默认键物化，加载即有效值——**出厂首启不报故障**。

**不启用 `FDB_KV_AUTO_UPDATE`**（`fdb_cfg.h` 维持现状）：该机制在版本号变化时会把缺失
键**静默补写**为默认值，CRC 坏而被跳过的 KV 会被它掩盖成"从未损坏"。关闭后，缺失/损坏/
语义非法的键如实报 b2 且不下发（§5）。恢复出厂 = `fdb_kv_set_default()`（扩展点：保留
寄存器已裁撤，如需上位机入口将在设备级块新增定义）；该操作掉电中断只留下部分缺失键，下次启动按
加载失败处理（对应通道不投入运行），可接受。

### 布局演进（仅开发期）

设备无在线升级、固件出厂即固定，KV 布局**仅在开发调试期演进**，生产后不存在迁移问题，
也不需要任何迁移机制：开发期改布局直接全片擦除/恢复出厂/上位机重下发，旧格式数据天然
落进既有防线（语义校验拒绝或 CRC 坏跳过 → b2、不顶替）。不设版本字段；不启用
`FDB_KV_AUTO_UPDATE` 补键（静默掩蔽 CRC 坏键，理由见上）。

## 7. 定时与容量

| 项目 | 数值 | 依据 |
| --- | --- | --- |
| 定时器/队列/事件 | 无 | 纯组件：由 `AoModbus` 直接调用 |
| RTC（`param_boot_load`） | ≤100 ms（一次性） | 4 KB 扫描 + CRC32 + 恢复；发生在 `QActive_start` 上下文（`QF_run` 前） |
| RTC（`param_save_*`） | ≤30 ms 最坏 | 写记录（≈92 B 字节编程+回读）+ GC 搬移/擦除 + 写后读回校验（≈1 ms）；**实测收口**。此窗口同时是 `AoModbus` 写回调的最长 RTC，驱动其队列/池预算（`ao_modbus.md` §7） |

## 8. 故障路径（三类，位定义见 `ao_modbus.md` §5）

| 故障 | 分类 | 处理 |
| --- | --- | --- |
| 固化写失败 | 合法异常（不可恢复） | EX 04 整笔拒绝 + b1 锁存；**无兜底**；操作人员重写寄存器即重试 |
| 加载失败（缺失/损坏/非法） | 合法异常（不可恢复，与初始化失败同级） | 不下发不顶替 + b2；等上位机下发配置后启动 |
| `fdb_kvdb_init` 失败 | 合法异常（不可恢复，产品报废级） | 无任何配置下发 + b3；Modbus 按默认地址运行 |
| 掉电（任意写时刻） | 预期环境 | 旧值或完整新值（§2），上电自动恢复 |
| 键名/格式演进 | 设计变更 | 仅开发期存在（§6 布局演进）；旧格式按加载失败处理（不下发不顶替） |

### 覆盖性审查：三类之外的情形（结论：分类完备；边界已定案）

运行期对 Flash 的反应点恰好三个（初始化/加载/固化），三类故障一一对应，**分类是完备的**。
其余 flash 相关情形要么映射进三类，要么不是故障：

| 情形 | 归类 | 说明 |
| --- | --- | --- |
| 掉电/复位打断写入 | **非故障** | §2 掉电保护：下次启动恢复出旧值或完整新值；EX 00/04 与恢复结果无分歧（EX 04 后恢复出新值属 Flash 硬件异常，§4 已注明报废级） |
| 掉电打断恢复出厂 | 加载失败（b2） | 部分键缺失，对应通道不投入运行（§6 已述） |
| 数据保持衰减（写入正确、存放后位衰减） | 加载失败（b2） | 下次启动 CRC 失败被跳过 = 键缺失；出厂前老化/高温试验可提前暴露 |
| `FDB_SAVED_FULL`（GC 后仍无空间） | 写入失败（b1/EX 04） | **重写不可修复**（容量问题，非瞬态）；本布局 3 KB 可用 vs ~1 KB 数据不会发生，GC 长稳验证看守 |
| 磨损寿命耗尽 | 写入失败（b1/EX 04） | 表现为编程/回读校验失败；变化检查 + 磨损均衡已是缓解 |
| GC 搬移失败（读旧 KV 失败） | 写入失败（b1/EX 04） | FlashDB 内部只记日志，最终以当次/后续写失败暴露（§2） |
| 恢复期坏扇区自动格式化失败 | 加载失败（b2） | FlashDB quirk：`check_sec_hdr_cb` 不检查 `format_sector` 返回值，扇区保持坏 → 键缺失 |
| Flash 读硬件错误 | 加载失败（b2）**+数据损失** | FlashDB 会把读失败扇区当坏扇区**自动格式化**——数据被销毁后表现为键缺失；归 b2，备注数据不可找回 |
| 写"成功"但内容与预期不符 | **已收口（设计内）** | 写后读回 memcmp：EX 00 ⟺ 读回=下发值，应答以 flash 实际状态为准，消灭"EX 04 但已固化"分歧角（§4）；残余仅为写与读回双重误判（报废级域） |
| 运行中读取 | 无此场景 | 确认：除启动加载外无读路径；GC 内部读属写路径。`fdb_kvdb_check()` 留作产线/维护完整性检查（可选） |
| 全片擦除/分区被整区格式化后上电 | **已定案：不区分** | 当作崭新空片：默认表物化、以出厂配置运行、不报故障（= 隐式恢复出厂语义）。运维约束：校准参数上位机留档、严守禁全片擦除（README） |



## 9. 验证矩阵（本模块）

| 测试 | 激励 | 预期 | 证据 |
| --- | --- | --- | --- |
| 差异检查 | 同值重复 FC16 写 ×100 | 0 次 flash 写、均 EX 00（日志计数） | RTT 计数 |
| 固化/回读 | 改配置→断电→上电 | 配置保持；通道行为一致 | 断电循环 |
| 写失败注入 | 固化时制造写失败 | EX 04、配置不生效、b1 锁存；重写后 EX 00 并清 b1 | 调试构建 |
| 读回校验 | 注入"写报错但实际落盘" | 读回一致 → EX 00（配置生效、snapshot 更新）；不再出现 EX 04 但已固化 | 调试构建 |
| 原子性 | 单块写帧固化失败 | 镜像/通道行为均不变（整笔拒绝） | 调试构建 |
| 地址固化 | FC06 写 128→断电→上电 | 新地址生效（旧地址静默）；`dev/addr` 保持 | 断电循环 |
| 出厂首启 | 空 flash 首次上电 | 默认表物化→加载有效→b2/b3 不置位；通道按默认配置先检后测 | 新板上电 |
| 损坏注入 | 翻转某通道 KV 值字节 | 该通道不投入运行（状态 1）+b2；其余通道正常启动 | 调试器改 flash |
| 部分加载 | 损坏 ch3+ch6 的 KV | 仅 ch3/ch6 不启动；其余 6 通道正常先检后测 | 调试器 |
| 语义非法值注入 | 改写为越界值（如 type=7） | 校验拒绝→b2、不下发 | 调试器 |
| 初始化失败 | 人为破坏分区（init 失败） | b3 且复位前不清；无通道启动；Modbus 默认地址运行可读到故障 | 调试构建 |
| 掉电窗口 | 固化瞬间反复断电 ≥100 次 | 每次上电旧值或新值+CRC 恢复日志，无半截值 | 自动断电夹具 |
| GC 长稳 | 连续写 1000 次 | 无 SAVED_FULL；固化 RTC 水位 ≤30 ms；扇区擦除轮转 | 日志统计 |
| 恢复出厂（扩展） | 调 `fdb_kv_set_default()` | 全部参数回默认并物化；b2/b3 不置位 | 调试构建 |
